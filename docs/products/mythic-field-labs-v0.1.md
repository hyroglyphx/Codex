Status: BUILDER CANDIDATE

Base research branch: `research/reconcile-state-2026-09-20`

## Purpose

Convert the existing myth/operator corpus into a coherent educational and commercial product family without splitting research truth from public products.

The product system inherits the Codex evidence spine and ARGO return requirement. A product is a Builder view over validated or explicitly labeled source material, never an independent truth system.

## Product conversion grammar

SOURCE → ENCOUNTER → OPERATOR → MODEL → EXPERIMENT → ADVERSARY → ROSETTA → TRANSFER → RETURN

Every unit must declare, at minimum:

- source/witness basis;
- carrier or encounter;
- active operator;
- preserved invariant;
- transformation/transport;
- residue or loss;
- boundary/failure case;
- learner action;
- return path to source;
- authority/maturity label for claims.

## Release rule

Depth belongs in the source/reference layer. The public paid object should expose enough depth to produce transformation without becoming an archive dump.

Recommended first-wave scale:

- 4 flagship Field Labs;
- 48 principal encounters total;
- 48 core cards;
- 12–16 printable experiments/boards;
- 4 free samplers;
- approximately 20–27 short audio episodes;
- 4 living web nodes.

This is enough material to establish a recognizable system while still allowing completion and measurement.

## Flow problem: zero transactions → first repeatable flow

The first commercial objective is not revenue maximization. It is to discover a repeatable conversion path.

Model the visitor state as:

U0 = unaware
U1 = curious
U2 = engaged
U3 = identified/returning
U4 = first transaction
U5 = repeat transaction/support
U6 = advocate/referrer

A transaction includes a purchase or donation, but these must remain distinguishable events.

For transition i→j define:

p_ij = N(j) / N(i)

The current zero-sales/zero-donation condition means the system has not yet identified which transition is broken. Traffic alone cannot distinguish weak discovery, weak comprehension, weak trust, weak offer fit, weak price fit, or checkout friction.

Therefore instrument the path before scaling the catalog.

### Minimum conversion ladder

1. Free encounter: a useful web node, card, mini experiment or sampler that works without payment.
2. Return invitation: download/save/email or a clearly related next encounter.
3. Entry transaction: one inexpensive complete object with obvious value and immediate delivery.
4. Core product: full Field Lab or themed bundle.
5. Patron/support path: donation/support presented separately from purchasing educational value.
6. Return path: purchaser/supporter is routed into the next logically adjacent operator rather than a generic store page.

### Initial offer architecture

- Free: one complete mini-lab or sampler per mythic cycle.
- Entry: $3–$7 printable/card/mini-lab object.
- Core: $9–$19 Field Lab digital edition.
- Bundle: $29–$49 founding-four collection after at least two individual labs exist.
- Support: optional donation/patron route with no artificial gating of already-free scholarship.

Prices are Builder hypotheses, not canonical truths. Test them.

## Measurement contract

Do not optimize raw views first. Record the smallest useful funnel:

landing_view → meaningful_engagement → sampler_open/download → product_view → checkout_start → purchase_complete

and separately:

support_view → donation_start → donation_complete

Also record:

- source/referrer;
- myth/cycle;
- encounter/operator;
- free versus paid object;
- price/version;
- return visit;
- downstream next-object click.

The first target is not a large number. It is a non-zero closed loop that repeats: stranger → useful encounter → trust → transaction → return.

## First validation gates

Gate 1 — Engagement: can one free Theseus encounter reliably move visitors to a second meaningful action?

Gate 2 — Intent: will engaged visitors open the sampler/product page or begin checkout?

Gate 3 — Transaction: can the same offer generate more than one independent purchase/support event?

Gate 4 — Repeatability: can the path work across at least two mythic cycles or two acquisition sources?

Gate 5 — Retention: does any buyer/supporter return for another object?

Do not interpret a single purchase as product-market fit. Do interpret it as proof that the zero barrier can be crossed and as evidence about the path that crossed it.

## Builder invariant

Do not manufacture more inventory to compensate for an unobserved conversion path.

The catalog grows only when the previous release teaches us something about discovery, engagement, trust, transaction, return, or transfer.
